# Study protocol and consent draft

Preparation only · 31 October 2026 · [Study kit](README.md)

## Before scheduling

Bind each session to the exact candidate version/build, executable and DMG SHA-256, tested Mac/OS and receiving app/browser version. Complete inherited native/signing gates before participant distribution. Use the same non-sensitive original fixtures and tasks for everyone. Prepare a fictional one-page Website brief, a synthetic layout image, a plain writing-rules prompt, one two-field template and a checklist. Do not ask anyone to expose their real chats, paid AI account, source files or clipboard history.

Record eligibility (role and current reuse workflow) without collecting employer, client or proprietary content. Record a local timezone for the seven-day diary. Pilot task wording separately and label pilots; do not quietly count assisted pilots toward the eight-person gate.

## Consent script

“We’re testing Nivlet, a free Mac utility for reusable prompts, files and notes. We’re testing the app, not you. We’ll observe a short task and ask you to record any voluntary use over seven days. Use only the supplied fictional work. We’ll note task outcomes, assistance, timing, friction and days used under a participant code. There is no background tracking. Participation is optional; you can skip a task, stop or withdraw without giving a reason. Keeping the app is optional. We won’t collect real chats or working libraries. Recording is off unless you separately agree. Before you agree, we’ll give you the study contact, withdrawal route and retention period.”

Before any observation, confirm the actual contact/retention text and record consent date/version privately. Ask recording consent separately; a refusal must not prevent participation. Do not record a whole personal desktop. At the end, let the participant review any excerpt proposed for the report. Do not treat installation or an invitation reply as consent.

## Baseline, then Nivlet

1. Ask: “How would you normally retrieve a rule, adapt a familiar request, attach a reference and save the next question?” Let them use a non-sensitive copy of their existing Notes/folders/snippets approach. Record actions, search/window switches, assistance and time boundaries. Don't claim measured improvement if this baseline is missing.
2. For the Nivlet task, provide the same fictional project material and the ordinary first-run choices. Start timing when the task is handed over; record installation/first-run time separately. Do not explain the solution in advance.
3. Say: “Return to the Website work. Find the saved writing rules, review them, and place them in the provided local text document. Adapt the explanation prompt for ‘design systems’ and ‘a new teammate’, inspect the complete result, then place it below the rules. Find the layout reference and attach it to the provided local receiving document/folder. Record ‘check mobile layout next’ for your next visit. Return to the work.” Copy/paste is deliberate. If an approved external AI destination is used later, separately record the actual upload completion; don't send to an AI service for this local study by default.
4. Observe **open → find → copy/fill/attach → return**. Check copied text equals preview and the received file has its original bytes. Record task failures and receiving-app refusals independently. A fallback can count as task completion only if found without researcher guidance; retain that distinction in the notes.
5. Ask the participant to switch to a second pocket and find its note, then return. This supplementary task checks project separation; do not substitute it for the core flow.
6. After the outcome, ask what was unclear, which part would replace their existing method, and what they would leave in Notes/folders. Avoid “wasn’t that faster?” or other leading prompts.

## Assistance and stopping

Mark each task `unaided`, `assisted`, `failed`, `skipped` or `not_observed`. “What are you looking for?” is a neutral think-aloud prompt. Naming a control, explaining a shortcut, showing a fallback or demonstrating the next action is assistance. Record the first help time and exact intervention. If they ask for help or remain stuck for two minutes, offer help and label the outcome assisted. Stop immediately for data loss, permission surprises, distress or accidental private content exposure; retain recoverable data and log the incident without copying private content.

Core unaided success requires every core step and a return to the original work without task-solving assistance. An incomplete/failed step makes the full flow incomplete. Observe errors even when the final result succeeds.

## Seven-day return use

Give a manual diary and explain that use is voluntary; no reminders that instruct them to use the app. Any authorized reminder about reporting must be logged. Count distinct participant-local calendar dates in a defined seven-day window. Separate initial study-day use from voluntary return dates and disclose whether the threshold includes that initial date. Proposed primary measure: three voluntary-use dates **after** the observed session, in the next seven calendar days. Keep this choice fixed before recruitment.

Ask the participant to log a date, whether they used it, what kind of task (no content), how they know, and any friction. At the end ask “Would you keep Nivlet installed for your own work?” Record yes/no/unknown, whether it remains installed when volunteered, and the reason. Intent and observed installation are different fields. No remote inspection or app telemetry.

## Evaluate

Use the report template. Show the recruited, eligible, consented, completed, followed-up and withdrawn counts. Report 6/8, 5/8 and 4/8 only when the actual cohort and definitions support those numbers. Separate self-reported return dates from directly observed behavior. Missing or incomplete data keeps the validation gate unresolved. The final decision is proceed, revise/retest or defer, with rationale and sample limitations; passing a small study does not waive native/distribution gates or authorize launch.
